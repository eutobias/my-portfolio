# Portfolio Agent Instructions

A personal portfolio built with **Next.js 16 + PayloadCMS 3.85** as a single hybrid app. The CMS serves the admin panel and REST/GraphQL API; the frontend serves the public portfolio.

> **Ignore the `old/` folder** — it is a legacy Next.js Pages Router portfolio kept only for reference.

## Architecture

```
src/app/
├── (frontend)/   # Public portfolio pages
└── (payload)/    # ⚠️ AUTO-GENERATED by @payloadcms/next — do not edit manually
src/collections/  # Payload CMS collection definitions (Users, Media)
src/payload.config.ts  # Main Payload configuration
src/payload-types.ts   # ⚠️ AUTO-GENERATED — run `pnpm generate:types` after schema changes
```

Path aliases (see [tsconfig.json](tsconfig.json)):

- `@/` → `./src/`
- `@payload-config` → `./src/payload.config.ts`

## Build & Test Commands

| Command                   | Purpose                                                          |
| ------------------------- | ---------------------------------------------------------------- |
| `pnpm dev`                | Start dev server                                                 |
| `pnpm devsafe`            | Clear `.next` cache then dev (use when dev behaves unexpectedly) |
| `pnpm build`              | Production build                                                 |
| `pnpm lint`               | ESLint                                                           |
| `pnpm test`               | All tests (integration + e2e, sequential)                        |
| `pnpm test:int`           | Vitest integration tests (`tests/int/**/*.int.spec.ts`)          |
| `pnpm test:e2e`           | Playwright e2e tests (`tests/e2e/**/*.e2e.spec.ts`)              |
| `pnpm generate:types`     | Regenerate `src/payload-types.ts` from Payload schema            |
| `pnpm generate:importmap` | Regenerate Payload admin import map                              |

## Environment Variables

No `.env.example` exists. Create `.env` manually with:

```
PAYLOAD_SECRET=<any-random-string>
MONGODB_URI=mongodb://127.0.0.1/my-portfolio   # local
# MONGODB_URI=mongodb://mongo/my-portfolio     # docker-compose
BLOB_READ_WRITE_TOKEN=<vercel-blob-token>      # optional, for Vercel Blob storage
```

Docker: run `docker-compose up` to start MongoDB + app together.

## Key Conventions

- **TypeScript strict mode** is enabled — all types must be explicit, no implicit `any`.
- After modifying any file in `src/collections/` or `src/payload.config.ts`, run `pnpm generate:types`.
- The `(payload)/` route group (layout, admin routes, API routes) is managed by `@payloadcms/next` — changes there are overwritten on regeneration.
- Package manager: **pnpm** (`^9 || ^10`). Do not use npm or yarn.
- E2E tests seed a test user `dev@payloadcms.com / test` via [tests/helpers/seedUser.ts](tests/helpers/seedUser.ts).
