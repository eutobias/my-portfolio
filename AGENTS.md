# Portfolio Agent Instructions

A personal portfolio built with **Next.js 16 + PayloadCMS 3.85** as a single hybrid app. The CMS serves the admin panel and REST/GraphQL API; the frontend serves the public portfolio.

> **Ignore the `old/` folder** — it is a legacy Next.js Pages Router portfolio kept only for reference.

## Architecture

```
src/app/
├── (frontend)/   # Public portfolio pages
└── (payload)/    # ⚠️ AUTO-GENERATED by @payloadcms/next — do not edit manually
src/collections/  # Payload CMS collection definitions (Users, Media)
src/payload.config.ts  # Main Payload configuration
src/payload-types.ts   # ⚠️ AUTO-GENERATED — run `pnpm generate:types` after schema changes
```

Path aliases (see [tsconfig.json](tsconfig.json)):

- `@/` → `./src/`
- `@payload-config` → `./src/payload.config.ts`

## Components

Reusable UI components located in `src/components/`:

### Base Components (`src/components/base/`)
- **Box** — Flexible layout wrapper (defaults to `div` with `flex` display)
- **Button** — Styled button with variants (`primary`, `secondary`, `tertiary`) and sizes (`sm`, `md`, `lg`)
- **ButtonLink** — Link component styled as a button
- **Grid** — Grid layout component for multi-column layouts
- **Heading** — Semantic heading component with sizes (`sm`, `md`, `lg`, `xl`) and weights (`regular` to `extrabold`)
- **Text** — Text component with semantic meaning (body, caption, etc.) and customizable styling

### Feature Components (`src/components/`)
- **Header** — Main header component with Logo and Navigation; uses Box as layout container
- **Logo** — Brand logo/wordmark linking to home page; uses Heading for typography
- **Navigation** — Navigation menu with ButtonLink items for main site pages
- **Footer** — Footer with copyright and social media links; uses Box, Text, Heading, and Button components
- **ThemeSwitcher** — Interactive theme selector with palette icon; fixed bottom-right position; uses Box, Button, Heading, and Text

All components use CSS custom properties for theming (`--theme-*`, `--font-*`, `--text-*`, `--spacing-*`).

## Build & Test Commands

| Command                   | Purpose                                                          |
| ------------------------- | ---------------------------------------------------------------- |
| `pnpm dev`                | Start dev server                                                 |
| `pnpm devsafe`            | Clear `.next` cache then dev (use when dev behaves unexpectedly) |
| `pnpm build`              | Production build                                                 |
| `pnpm lint`               | ESLint                                                           |
| `pnpm test`               | All tests (integration + e2e, sequential)                        |
| `pnpm test:int`           | Vitest integration tests (`tests/int/**/*.int.spec.ts`)          |
| `pnpm test:e2e`           | Playwright e2e tests (`tests/e2e/**/*.e2e.spec.ts`)              |
| `pnpm generate:types`     | Regenerate `src/payload-types.ts` from Payload schema            |
| `pnpm generate:importmap` | Regenerate Payload admin import map                              |

## Environment Variables

Create `.env.local` with the following variables:

```env
# Payload CMS
PAYLOAD_SECRET=<any-random-string>

# MongoDB
MONGODB_URI=mongodb+srv://<user>:<password>@cluster.mongodb.net/?retryWrites=true&w=majority
# Local development alternative:
# MONGODB_URI=mongodb://127.0.0.1/my-portfolio

# Vercel Blob Storage
BLOB_STORE_ID=<vercel-blob-store-id>
BLOB_READ_WRITE_TOKEN=vercel_blob_rw_<token>

# Email Service (Mailgun)
MAIL_GUN_API_KEY=<mailgun-api-key>
MAIL_GUN_SANDBOX_DOMAIN=<mailgun-sandbox-domain>
MAIL_TO=<recipient-email>

# Vercel OIDC (for Vercel deployments)
VERCEL_OIDC_TOKEN=<vercel-oidc-token>
```

### Local Development Setup

For local development without Vercel services:
```env
PAYLOAD_SECRET=dev-secret-key
MONGODB_URI=mongodb://127.0.0.1/my-portfolio
```

Then run `docker-compose up` to start MongoDB, or use an existing MongoDB instance.

## Key Conventions

- **TypeScript strict mode** is enabled — all types must be explicit, no implicit `any`.
- After modifying any file in `src/collections/` or `src/payload.config.ts`, run `pnpm generate:types`.
- The `(payload)/` route group (layout, admin routes, API routes) is managed by `@payloadcms/next` — changes there are overwritten on regeneration.
- Package manager: **pnpm** (`^9 || ^10`). Do not use npm or yarn.
- E2E tests seed a test user `dev@payloadcms.com / test` via [tests/helpers/seedUser.ts](tests/helpers/seedUser.ts).
